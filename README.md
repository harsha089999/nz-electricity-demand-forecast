# NZ Electricity Demand Forecast

[![Run project](https://github.com/harsha089999/nz-electricity-demand-forecast/actions/workflows/run.yml/badge.svg)](https://github.com/harsha089999/nz-electricity-demand-forecast/actions/workflows/run.yml)

**Half-hourly demand forecasting with lag, calendar and weather features and a proper time-based backtest.**

> **About the data:** everything in this repo is simulated, generated by the code with a fixed random seed so results are reproducible. The numbers describe the simulation, not the real world. Each project says how to swap in a real dataset.

## The business question

What will half-hourly electricity demand look like tomorrow, and how much do temperature and public holidays matter?

## What this project does

Electricity demand is a good forecasting problem: half-hourly, strongly seasonal and driven by things anyone understands (cold mornings, weekends, holidays). This project frames forecasting as supervised learning with lag and calendar features, then evaluates it with a time-ordered split so there is no leakage.

## The data

Half-hourly data from 1 October 2025 to 15 October 2026 (about 18,000 rows): temperature with seasonal and daily cycles, and demand with a morning peak (about 8am) and an evening peak (about 6:30pm), roughly 25% lower on weekends and holidays, extra heating load below 14 C, plus noise. The holiday list is a short illustrative list of dates, not an official calendar.

## How it works

1. Build features: half-hour of day, day of week, month, holiday flag, temperature, heating degrees (max(14 - temp, 0)), demand at the same time yesterday and last week, and the 24-hour average ending one day earlier.
2. Split by time: train before 1 August 2026, leave August as a gap, test from 1 September 2026. No shuffling.
3. Fit `HistGradientBoostingRegressor` (400 iterations, learning rate 0.05) and compare with a naive baseline: demand at the same time last week.
4. Report MAPE overall and by hour of day.

## Run it

```bash
git clone https://github.com/harsha089999/nz-electricity-demand-forecast
cd nz-electricity-demand-forecast
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python src/main.py
```

It runs in about 15 seconds or less on a laptop and writes its files to `outputs/`. Python 3.10 or newer is recommended.

## Results from the included run

This is the actual console output when the script is run as shipped:

```text
Naive (same time last week) MAPE: 2.95%
Gradient boosting MAPE:            1.50%
Worst hours: [{'hour': 10, 'mape_pct': 1.79}, {'hour': 16, 'mape_pct': 1.74}, {'hour': 12, 'mape_pct': 1.73}]
```

Gradient boosting roughly halves the naive baseline's error (1.50% vs 2.95% MAPE). The weakest hours are mid-morning and mid-afternoon, still under 1.8%. These figures describe the simulation. The test window is spring only, so performance in a cold-snap winter peak is not tested.

## Output files

| File | What it contains |
|---|---|
| `outputs/predictions.csv` | Test-period actuals, naive and gradient boosting predictions, temperature and holiday flag. |
| `outputs/error_by_hour.csv` | MAPE of the boosted model by hour of day. |

## Limitations and honest caveats

- The model uses observed temperature. In real use you only have a weather forecast, which adds error.
- A single train/test split. Rolling-origin backtesting across several periods would be more convincing.
- No winter in the test window, and no regional breakdown.
- The holiday list is illustrative and incomplete.

## Using real data

Electricity Authority EMI (emi.ea.govt.nz) publishes grid and regional demand data. Pair it with temperature from NIWA CliFlo or Open-Meteo, build a table with `ts, temp_c, demand_mw`, and replace `make_data()`. Use a full NZ public holiday calendar from data.govt.nz.
